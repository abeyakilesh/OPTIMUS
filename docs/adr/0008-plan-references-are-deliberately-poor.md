# ADR-0008 — Plan references are deliberately poor, and resolve through the artifact store

**Status:** accepted · **Date:** 2026-08-26

## Context

A mission is a DAG, and until now its edges carried nothing. `Scheduler.execute()`
discarded `outcome.output` and every step's input was frozen at plan time:

```
$ grep -n "output" kernel/scheduler.ts
(no matches)
```

`dependsOn` was a **timing** edge. Two places proved it by working anyway — the
walking-skeleton demo in `kernel/cli.ts` and AC-1 in the acceptance suite both
gave `html.extractTitle` a constant `addressOf(FIXTURE_HTML)` computed in the
caller, which happened to equal what `web.fetch` was about to produce. Delete
`dependsOn` from either and nothing changed. That is facade #2 from the audit,
sitting inside the demo whose job is proving the pipe works end to end.

This is also the last thing the plan compiler (PR C) needs before it can emit a
mission with more than one useful step.

## Decision

**1. The syntax is one shape and nothing else.**

```json
{ "$from": "<stepId>.<outputField>" }
```

One dot. One declared output field. No paths into the value, no array indexing,
no transforms, no expression language, no fallbacks, no defaults. Everything it
cannot express is written down as a limit rather than discovered later as a gap.

A plan language grows one convenience at a time until it is a programming
language nobody designed. This one has to be validated by a machine and
generated by a model, and both of those get harder with every feature.

**2. A reference may sit anywhere in the input tree; the reference itself is
flat.** "No nesting" is a rule about the reference, not about where it may
appear. The case that forced this is real: `llm.chat` takes
`messages: [{ role, content, trust }]`, so piping a previous step's output into
a message is a nested position or it is nothing.

**3. Presence of the key decides; well-formedness is checked separately.** There
is no `isReference(v: unknown): v is StepReference` in this codebase, and that
is deliberate — #65 and #66 each found a type predicate that checked less than
it asserted, and TypeScript never verifies a predicate's body. Instead
`holdsReferenceKey` returns a plain boolean about the key, and `parseReference`
throws with the reason. The consequence is the point: **a malformed reference
can never be silently passed through as a literal.** `{"$from": "fetch"}` is a
missing dot, not a value.

**4. References are validated at PLAN TIME, against five things:** the named
step exists, it is not this step, it is in `dependsOn`, the reference is
well-formed, and the producing capability *declares that output field*. The last
became possible only in ADR-0007; before it, a bad reference could fail no
earlier than the middle of a running mission.

The `dependsOn` check is the structural kill of facade #2. A reference to a step
you do not depend on is not a data flow — the scheduler may run both at once, so
it is a race.

**5. Resolution goes through the artifact store, via the event log.** A passed
step's output is sealed into the store and its address recorded as
`evidence.outputArtifactId`. Resolution reads the log for the producing step's
`step.finished`, takes that address, and reads the bytes back.

The alternative — a `Map<stepId, unknown>` on the scheduler — is simpler and
wrong. It lives exactly as long as one process, so a mission resumed from its
log would resolve every reference to `undefined` while every gate stayed green.
The landing page already ships `{ name: "Proof", note: "reproducible" }`; this
is the difference between that being true and being a facade.

**6. A step whose input cannot be assembled is a failed STEP, not a thrown
mission.** See the consequences.

## Consequences

**Good**

- The walking skeleton is a pipeline instead of two steps that agree. A test now
  fails if the edge is made decorative again: change what `fetch` returns, and
  `extract`'s title has to change with it.
- Plan-time validation means an invalid plan is refused before any work is done,
  which is what makes a mission a proposal that can be rejected rather than a
  program that fails halfway.
- `kernel/cli.ts` runs in CI for the first time, and the tests pin **which gate**
  each demo demonstrates rather than that one is green and the other red.
- The trace shows the data flow. `step.resolved` records what each reference
  pointed at, and the CLI prints it.

**Bad, accepted**

- **The syntax cannot express most things.** Named, so none of these is
  discovered later as a surprise: no field of a field (`fetch.meta.etag`), no
  array element (`relocate.matches[0]`), no dereferencing an artifact id into
  its content, no literal/reference concatenation, no default when a step was
  skipped. The first plan that needs one of these is a decision to reopen this
  ADR, not a bug.
- **Artifact dereferencing is the gap that will be felt first.** `web.fetch`
  returns an `artifactId`, not the page text, so piping a fetch into anything
  that wants a string still needs a capability in between.
- **Every passed step now writes one extra artifact.** Content-addressed, so
  identical outputs dedupe, but a long mission stores more than it did.
- **`producedArtifactIds` grew by one entry per passed step**, and three tests
  asserted the old exact lists. Two of those turned out to have been captured by
  ADR-0007's output door and to have been passing for the wrong reason since —
  recorded under `new-door-inherits-old-failures`.
- **The resolution failure path had to be reworked mid-PR.** Throwing out of
  `Scheduler.execute` discarded the whole event log, including evidence for
  steps that had already passed. Found by this feature's own mutation test and
  recorded as `error-path-discards-evidence`.

## Supersedes / relates
